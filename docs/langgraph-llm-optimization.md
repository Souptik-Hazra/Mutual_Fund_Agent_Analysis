# LangChain and LangGraph LLM-load optimization

## Audited architecture

The research assistant compiles a three-node LangGraph: deterministic intent planning, deterministic specialist execution, and optional narrative synthesis. The eight specialist capabilities are fund, category, actual investor exposure, portfolio, security, events, social, and documents.

Specialist calculations and retrieval are performed by existing Python analytics and data services. The graph passes one SQLAlchemy session through the specialist node, so the specialist loop remains sequential; concurrent use of that session would not be a safe latency optimization.

## Changes

- Added `synthesize` to the assistant request schema. It defaults to `false`, so ordinary structured research does not incur an LLM request.
- LLM narrative synthesis remains available by setting `synthesize: true` on a request.
- Removed the graph-level retry wrapper around `model.invoke`. The provider factory already configures LangChain model retries, so nesting another retry layer could multiply attempts.
- Added structured log fields for synthesis call count, elapsed milliseconds, model, and provider-reported input/output/total tokens when available.
- Exposed the opt-in behavior in the assistant capabilities endpoint and the React assistant panel.
- Added tests proving the default path makes no LLM call and the opt-in path invokes synthesis once.

## Baseline and measurement limits

Before this change, each research request with at least one result group attempted one synthesis call, regardless of whether the question required narrative interpretation. The graph also wrapped the provider's own retry configuration with another retry layer.

After this change, the default path makes zero synthesis calls. An explicit `synthesize: true` request makes one graph-level synthesis invocation; provider retries remain governed by the configured LangChain provider client.

No paid provider credentials or live provider calls were used for this change. Therefore no real-world token, cost, or latency reduction percentage is claimed. Runtime logs now expose provider-reported usage and measured synthesis latency for a future like-for-like benchmark.

## Deliberately not changed

- Financial metrics remain deterministic and are not generated by an LLM.
- The eight specialist responsibilities and API response fields are preserved; `synthesize` is an additive request field.
- No specialist nodes were parallelized because they share a SQLAlchemy session.
- External market-data provider calls and their source-specific caching policies were not changed in this LLM-focused pass.
- Prompt evidence remains bounded by the existing 18,000-character cap; review and redesign that evidence budget separately against provider context limits and evidence completeness.
